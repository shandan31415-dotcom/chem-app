> 环境 ID：`cloud1-d8gy20yyt95635d5f`
> 目的：政策、参考价、企业园区名录都不用发版就能更新

## 一、现在的数据是怎么走的

2026-11-26 改过一次架构。以前是「GitHub 采集 → GitHub 存 → 云函数搬」，三处都在境外，任何一处抽风小程序就停更。现在是：

```
云函数 syncData（腾讯云，国内机房）
   ├─ 直抓 11 个政府栏目 → 解析、判定、去重 → 写云库
   ├─ 直抓新浪期货主力连续 → 更新 24 个品种价格 → 写云库
   └─ 顺带同步企业园区名录（月级变化）
        ↓
云数据库 snapshot / catalog
        ↓
小程序启动时读（读不到就用本机缓存，再不行用包里那份）
```

**GitHub 现在只剩一个用途**：云库被清空时（首次部署、或误删集合），从仓库里的备份快照借一次底子。日常运行完全不经过它，断网也不影响。

## 二、要建三个集合

云开发控制台 → 数据库 → 新建集合，名字必须一字不差：

| 集合 | 放什么 | 权限 |
|---|---|---|
| `snapshot` | 政策 + 参考价 | **所有用户可读，仅创建者可写** |
| `catalog` | 企业与园区名录 | **所有用户可读，仅创建者可写** |
| `sync_log` | 云函数运行日志 | 默认即可（小程序不读） |

> **权限这一步不能省。** 默认是「仅创建者可读写」，而记录是云函数写的、没有 `_openid`，
> 用户端一条都读不到，页面会一直显示包里的旧数据，而且不报错——最难查的一种故障。

前两个集合如果没建，云函数会自己建（代码里有兜底），但权限仍是默认值，还是要在控制台改一次。

## 三、部署云函数

1. 开发者工具左侧找到 `cloudfunctions/syncData`
2. **右键 → 上传并部署：云端安装依赖（不上传 node_modules）**
3. 右键再点一次 **上传触发器**（定时改了：09:40 / 13:40 / 17:10 / 21:40，只传代码不会更新定时）
4. 云开发控制台 → 云函数 → syncData → 触发器，确认有四条

> 上传时提示「云函数目录位于 miniprogramRoot 内」是警告不是错误。`project.config.json`
> 已经把 `cloudfunctions` 排除出小程序包。

## 四、手动跑一次

云开发控制台 → 云函数 → syncData → 测试，参数留空 `{}`。

正常情况下返回长这样：

```json
{
  "ok": true,
  "mode": "local-crawl",
  "policies": 67,
  "policy_added": 0,
  "policy_sources": "11/11",
  "data_date": "2026-11-26 14:20",
  "prices": 24,
  "price_source": "新浪财经",
  "price_note": "sina",
  "catalog": "首次写入",
  "notes": [],
  "ms": 1200
}
```

逐项看：

| 字段 | 正常值 | 不对怎么办 |
|---|---|---|
| `policy_sources` | `11/11` | 少于 11 说明有政府站连不上，看 `notes` 里列了哪几个；偶发一两个不影响 |
| `policies` | ≥ 60 | 明显变少说明抓取异常，云库应保留原数据，检查 `notes` |
| `price_note` | `sina` | `sina-fail` 说明新浪连不上，价格沿用旧值 |
| `catalog` | `首次写入` / `已更新` / `今日已检查` | 出现「拉取失败」，多半是仓库里还没有 `catalog.json`，等推送成功后隔 12 小时再跑，或手动改 `checked_at` |
| `ms` | 1000~3000 | 超过 15000 说明有源在拖时间 |

## 六、名录怎么维护（重点）

以前加一家会员企业要改代码、重新发版、提审，一轮下来几天。现在：

1. 云开发控制台 → 数据库 → `catalog` → 点 `latest` 那条记录
2. 找到 `payload.cities`，它是个数组，每个元素是一个地市：
   ```
   payload.cities[0].parks[]        ← 这个市的园区
   payload.cities[0].enterprises[]  ← 这个市的企业
   ```
3. 直接编辑 JSON：加一条企业就复制相邻那条改字段，删就整条去掉
4. 保存后，小程序下拉刷新即可看到

**注意**：`payload.updated_at` 别去动它。云函数拿它和仓库里的备份比新旧，改了会让下次同步逻辑判断错乱（改晚了不动，改早了会被仓库那份盖回去）。

企业条目里各字段的含义：

| 字段 | 说明 |
|---|---|
| `name` | 企业全称，页面上直接显示 |
| `match` | 搜索关键词数组，用户搜这些词能命中 |
| `products` | 主要产品，一行写完 |
| `cats` | 对应品类 id 数组，关联到品类页 |
| `high` | 是否重点企业（地图热力按这个加色） |
| `note` | 一句话说明，写采购/供应特点，别写广告 |

## 七、以后怎么维护

**日常什么都不用做。** 云函数每天跑 4 次，失败会写 `sync_log`。

| 情况 | 做什么 |
|---|---|
| 改小程序界面 | 照常上传新版本 |
| 加/改企业、园区 | 控制台改 `catalog`（见第六节） |
| 政策源要增删 | 改 `cloudfunctions/syncData/policies.js` 的 `SOURCES`，重新上传云函数 |
| 政策判定规则要调 | 改 `policies.js` 里的关键词表，重新上传；规则一改，历史条目下次跑会自动重算标签 |
| 想立刻看最新 | 小程序下拉刷新 |
| 怀疑数据没更新 | 控制台 → 云函数 → 日志，搜 `sync ok` 或 `sync_log` 集合 |

**费用**：云函数每次 1~2 秒，每天 4 次，一个月不到 4 分钟运行时间，免费额度用不到 1%。

## 八、出问题怎么查

| 现象 | 原因 | 处理 |
|---|---|---|
| `policy_sources` 少于 11 | 某个政府站在维护或改版 | 看 `notes` 里是哪几个；连续几天都失败才需要改 `SOURCES` 里的地址或正则 |
| `policies` 突然变少 | 抓取异常，云库本应保留原数据 | 如果确实变少，说明历史数据被合并规则吞了，查 `policies.js` 的去重段 |
| 小程序还是旧数据 | 集合权限没改 | 改成「所有用户可读」 |
| 提示「当前为离线数据」 | 云库没 `latest`，或环境 ID 不对 | 看 `snapshot` 有没有记录；对一下 `utils/config.js` |
| `catalog` 一直「拉取失败」 | 仓库里没有 `catalog.json`，或 GitHub 连不上 | 名录是月级数据，旧一点不影响；等下次 |
| 名录改了没生效 | 云函数下次同步用仓库那份盖回来了 | 检查 `payload.updated_at` 是否被改小 |
| 上传云函数 npm install 失败 | 网络 | 重试；或在目录下用终端手动 `npm install` 再上传 |

## 九、不想用了怎么退回

`mini/utils/config.js` 里清空环境 ID：

```js
const CLOUD_ENV = '';   // 清空即完全走代码包内的静态数据
```

重新编译发版即可。云函数和集合留着不产生费用，也可以到控制台删掉。

## 十、技术细节

| 环节 | 位置 | 说明 |
|---|---|---|
| 政策采集 | `cloudfunctions/syncData/policies.js` | 11 个源并发抓、关键词判定、书名号去重、增量累积（保留 150 条 / 12 年） |
| HTTP | `cloudfunctions/syncData/http.js` | 支持 http 协议、301/302 跳转、gzip/br 解压——山东三个站是明文 http |
| 主流程 | `cloudfunctions/syncData/index.js` | 政策与行情并行抓；任一条失败都保留云库旧值；结构校验不过就不写库 |
| 小程序端 | `utils/live.js` | 三级回退、10 分钟冷却、8 秒超时；快照与名录并行拉，互不阻塞 |
| 页面响应 | `pages/policies`、`pages/parks`、`pages/weekly` | `live.onUpdate()` 订阅，数据到了自动重绘 |
| 快照生成 | `mini/scripts/build_data.py` | `dump_cloud()` 出政策与行情，`dump_catalog()` 出名录 |
| 本地自测 | `mini/tools/test_sync.js`、`test_policies.js` | 不部署也能跑：`MOCK_EMPTY` / `MOCK_OFFLINE` / `MOCK_POLICY_DOWN` 三种故障场景 |
| 备份通道 | `.github/workflows/daily.yml` | 每天 1 次（北京 06:00），只做历史留档和冷启动底子，失败不影响小程序 |

周报页已经能用（转发 + 复制成纯文字发群），但**主动推送**需要微信订阅消息，还差一个模板 ID：

1. 微信公众平台 → 订阅消息 → 选用模板（选「内容更新提醒」类）
