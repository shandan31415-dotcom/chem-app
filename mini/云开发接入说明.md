# 云开发接入说明

> 环境 ID：`cloud1-d8gy20yyt95635d5f`
> 目的：让「政策 / 参考价 / 数据日期」不用重新发版也能更新

---

## 一、这一步解决什么问题

小程序是静态包，代码打包进去什么就是什么。之前政策更新了要重新编译、重新上传、重新提审，一条政策折腾一轮。

接上云开发之后变成这样：

```
GitHub Actions 每天抓数据
        ↓ 提交 cloud_snapshot.json
GitHub Pages 自动发布
        ↓ 云函数每天 06:30 去拉
云数据库 snapshot/latest
        ↓ 小程序启动时读
用户看到的政策 / 参考价
```

用户端还有一层兜底：**云库读不到 → 用本机上次缓存 → 再不行用包里那份**。所以云函数挂了、断网了、环境 ID 写错了，页面都照常打开，只是数据停在上一版。

## 二、前置条件（很重要）

云函数是从**线上**拉 `cloud_snapshot.json` 的，本地文件它看不见。所以：

> **先把代码推到 GitHub，等约 1 分钟 Pages 部署完，再去点云函数。**

验证方法：浏览器打开下面这个地址，能看到一大段 JSON 就说明线上有了。

```
https://shandan31415-dotcom.github.io/chem-app/data/cloud_snapshot.json
```

看不到（404）就先别往下走，云函数跑了也是白跑。

## 三、三步操作

### 步骤一：建数据库集合

1. 微信开发者工具顶部工具栏 → **云开发**
2. 左侧选 **数据库**
3. 点 **+** 新建集合，名字填 `snapshot`（**必须一字不差**，小写）
4. 集合建好后，点集合右上角的 **权限设置**，改成：

   ```
   所有用户可读，仅创建者可写
   ```

   > **这一步不能省。** 默认是「仅创建者可读写」，而记录是云函数写的、没有 `_openid`，
   > 用户端一条都读不到，页面会一直显示包里的旧数据，还查不出原因。

5. 再建一个集合 `sync_log`，权限随意（只给云函数写日志用，用户端不读）。

### 步骤二：上传云函数

1. 开发者工具左侧文件树找到 `cloudfunctions/syncData`
2. **右键这个文件夹 → 上传并部署：云端安装依赖（不上传 node_modules）**
3. 等 1~2 分钟，文件夹图标变成一朵小云就算成功
4. 到 **云开发控制台 → 云函数 → syncData → 触发器**，确认有一条 `dailySync`（每天 06:30）

   > 触发器来自 `cloudfunctions/syncData/config.json`，上传时会一起带上。没看到触发器就手动加一条定时触发，cron 填 `0 30 6 * * * *`。

> 上传时如果弹出「云函数目录位于 miniprogramRoot 内」的提醒，是**警告不是错误**，
> 可以忽略——`project.config.json` 里已经把 `cloudfunctions` 排除出小程序包了。

### 步骤三：先手动跑一次

云库现在是空的，不等第二天，直接催一次：

1. **云开发控制台 → 云函数 → syncData → 测试**
2. 测试参数留空 `{}`，点运行
3. 返回结果里看到 `"ok": true` 就成了，例如：

   ```json
   { "ok": true, "source": "github-raw", "policies": 50, "data_date": "2026-11-24 14:00", "ms": 1284 }
   ```

4. 回到 **数据库 → snapshot**，应该能看到一条 `_id` 为 `latest` 的记录

如果返回 `"ok": false`，看返回里的 `errors` 数组，那是每个数据源失败的原因（见第六节）。

## 四、怎么确认小程序端用上了

1. 开发者工具里点 **编译**（或 Ctrl+B）
2. 进「化工政策」页，往下拉一下 → 顶部提示 **「已同步最新」**（不是「当前为离线数据」）
3. 页面底部那行提示会多出「（云端已同步）」

想验证得更彻底：去云开发控制台把 `snapshot/latest` 里的某条政策标题改几个字，再下拉刷新，页面上跟着变，就说明通道是通的（验证完记得改回去，或直接重新跑一次云函数覆盖）。

## 五、以后怎么维护

**什么都不用做。** 每天 06:30 云函数自动跑；GitHub 那边每天 3 次抓数据。

以下情况需要动一下：

| 情况 | 做什么 |
|---|---|
| 改了小程序的代码 | 照常上传新版本，和云开发无关 |
| 换了云开发环境 | 改 `utils/config.js` 的 `CLOUD_ENV`，重新发版 |
| 云函数报错 | 云开发控制台 → 云函数 → 日志，看 `sync fail` 那几行 |
| 想立刻看到最新数据 | 小程序里下拉刷新（政策页、参考价页都支持） |

**费用**：免费额度 3000 资源点/月，我们每天一次读写、用户端几十次读取，用不到 1%。超了会提示升级，不会直接扣钱。

## 六、出问题怎么查

| 现象 | 原因 | 处理 |
|---|---|---|
| 云函数返回 `ok:false`，errors 里全是 `timeout` | 云函数访问 GitHub 超时 | 正常现象，会自动换下一个源；四个都失败才报错。偶尔一次不用管 |
| 云函数成功，但小程序还是旧数据 | 集合权限没改 | 按步骤一第 4 点改成「所有用户可读」 |
| 小程序提示「当前为离线数据」 | 云库没有 `latest` 文档，或环境 ID 不对 | 控制台看 snapshot 里有没有记录；对一下 `utils/config.js` 的 `CLOUD_ENV` |
| 报 `collection not exists` | 集合没建 | 云函数会自动建，但权限可能是默认值，仍需手动改 |
| 上传云函数报 `npm install` 失败 | 网络问题 | 重试一次；还不行就在 `cloudfunctions/syncData` 目录下用图形化的「终端」跑 `npm install` 再上传 |
| 政策页条数比预期少 | 云端快照比包内旧，被拒绝了 | 这是保护逻辑。跑一次云函数刷新快照即可 |

## 七、不想用了怎么退回

把 `mini/utils/config.js` 里这一行清空：

```js
const CLOUD_ENV = '';   // 清空即完全走代码包内的静态数据
```

重新编译发版即可。云函数、集合留着不产生费用（免费额度内），也可以到云开发控制台删掉。

## 八、技术细节（给自己看）

| 环节 | 位置 | 说明 |
|---|---|---|
| 小程序端读库 | `utils/live.js` | 三级回退、10 分钟冷却、8 秒超时、结构校验；坏数据宁可不写 |
| 数据落点 | `utils/core.js` 的 `D.policies / D.prices / D.meta` | 直接改属性，页面里 `core.D.xxx` 全局生效 |
| 页面响应 | `pages/policies`、`pages/prices` | `live.onUpdate()` 订阅，数据变了自动重绘 |
| 云函数 | `cloudfunctions/syncData` | 4 个源依次尝试，都失败时**不动云库**，保留上一次快照 |
| 快照生成 | `mini/scripts/build_data.py` 的 `dump_cloud()` | 与包内数据同源同口径，避免云端和包里两套数 |
| 每日流程 | `.github/workflows/daily.yml` | 抓数据 → 重建小程序数据与快照 → 提交 → 触发 Pages |
